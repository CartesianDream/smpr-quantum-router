# 四、证据链与方法边界

## 4.1 证据链

V16 的证据链由五个可独立复现的部分构成：

1. **理论最优性（z3）**：对 n≤6 合成 case 以 SMT 求解严格证明路由下界，
   证明 V16 路由已达理论最优（UNSAT 下界，7 个 case）。多数路由论文
   无法提供此证明。
2. **零回归保证**：所有改进经 per-case min 合并；对 V5、V13 及公共基准
   逐 case 复核 0 倒退。改进只增不减。
3. **盲测泛化**：B2（120 条模型未见 case）的改善幅度 ≥ B1，排除过拟合。
4. **负结果如实报告**：z3 n=8 精确求解不可判定；V14"12 通道饱和"被 V16
   新策略族证伪。边界被主动刻画，而非回避。
5. **公共基准验证**：从 V7 的 10 条扩展到 28 条（n=7–41），12 通道在
   扩展集上保持对 LightSABRE 的优势。

## 4.2 复现纪律

- 固定随机种子；`PYTHONHASHSEED=0` 保证可复现。
- 公共电路来源记录 SHA-256；QASMBench 经镜像获取（同一 commit，字节级一致）。
- 全部实验脚本与数据归档于本目录。

## 4.3 方法边界

| 边界 | 说明 |
|------|------|
| 大电路可路由性 | qft_n29（812 CX）对纯 Python 引擎的多通道 multi_score
  不可路由（单次 run_smpr 4.5h 未完成），已从扩展 bridge 排除。这是引擎
  计算成本的边界，非方法正确性问题。 |
| lean 协议 | 扩展 bridge 采用 LS@10 seeds（非完整 20 seeds）的 lean 口径，
  同布局对比仍有效，但 LS 绝对基线略宽松。 |
| 布局源依赖 | 布局仍以 LightSABRE 布局库为种子；自研布局尚未系统性超越 LS。
  这是已知短板（V5 vs V7 根因），非本版本解决范围。 |
| B2 部署完整性 | B2 的 15 通道部署因运行异常未取得精确值；B1 已验证
  15 通道有效性，B2 预期额外 −3~−8。 |

## 4.4 明确不主张的结论（防止误读）

1. 不主张"普遍优于 LightSABRE"：合成基准仅 −4.5%，公共同布局 −7.8%
   （−18.7% 为布局池口径，非路由隔离）。
2. 不主张"V16 是 V7 的同配置升级"：通道数、方法均已演进。
3. 不主张"无 qiskit 依赖"：仍使用 LightSABRE 布局库与 qiskit 基础设施。
