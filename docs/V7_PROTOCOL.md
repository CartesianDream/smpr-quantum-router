# V7 外部验证预注册协议

## 1. 目的

V7 只回答四个此前未由 V5/V6 覆盖的问题：

1. SMPR 能否处理独立公共来源的线路；
2. 结论能否扩展到 Qiskit heavy-hex；
3. 结论能否扩展到 11–23 逻辑比特；
4. 在同一机器、相同线程策略和显式时间预算下，SMPR 与 LightSABRE 的
   质量—时间关系如何。

V7 不是新的调参集。清单冻结后，无论结果正负，都不得改变线路、拓扑规则、
参数、破平模式、重复次数或接受标准。

每次结果运行开始前，程序重新计算冻结清单中全部输入、核心模块和执行脚本的
SHA-256；任何缺失或差异都会在计时前终止。每次重复的 CSV 与环境 JSON 另有
结果哈希，最终分析要求三份结果清单全部通过且引用同一冻结清单。

## 2. 公共线路与许可证

线路来自 QASMBench 固定提交
`357b942396d5c2b7cbc1c229c585a6ef5ccaebac`。选择 10 条 11–23 比特线路，
覆盖搜索、算术、机器学习、量子内存、Bernstein–Vazirani、cat state 和
GHZ。每个源 QASM 在 `v7/manifest.json` 中给出 SHA-256。准备脚本同时保存
上游 LICENSE 与 NOTICE，论文应引用 DOI `10.1145/3550488`。

## 3. 规范化

QASM 由 Qiskit 2.4.2 载入。只删除末端测量和 barrier；发现中途测量、reset
或控制流即拒绝。随后在无耦合约束下、优化等级 0、种子 0，分解到 `u + cx`。

路由只依赖门的量子比特占用和 DAG 顺序，不依赖一比特旋转角。因此 V7 生成
“交互骨架”：保留每个 CX 及其顺序，把每个一比特门替换为 H 占位门。源
QASM、规范化 QPY/QASM、交互骨架与最终数据集分别哈希。V7 的正确性审计是
门依赖与映射轨迹审计；不能把它表述为对原始非 Clifford 线路的全幺正矩阵
等价证明。

准备过程采用事务式发布：所有源文件和规范化产物先在临时目录中完成检查，
只有 10 条线路全部通过后才写入正式 V7 目录。任何失败都必须在新解压目录
重新开始，不能把部分下载或部分规范化结果冻结。

## 4. heavy-hex

依据 Qiskit `CouplingMap.from_heavy_hex`：

- 11–19 逻辑比特使用距离 3、19 物理比特；
- 20–23 逻辑比特使用距离 5、57 物理比特；
- 图设为双向，路由质量只计抽象 SWAP；
- 逻辑比特少于物理比特时允许使用空闲物理点。

距离与物理比特数关系为
`n = (5 d^2 - 2 d - 1) / 2`，因此 `d=3` 得 19，`d=5` 得 57。

## 5. 同机质量—时间比较

每条线路重复三次。每次先执行一次不计时 LightSABRE 预热，然后计时 SMPR
候选生成与确定性选择；QASM/QPY 导出和统计分析不计入核心时间。LightSABRE
使用从 0 开始的确定性种子流顺序运行，记录达到 SMPR 时间预算的
`0.25×、0.5×、1×、2×` 时的当前最优质量。每个重复至少运行 20 个种子，
最多 10000 个。

记录字段包括 Python/Qiskit 版本、操作系统、CPU、逻辑/物理核数、线程环境、
每次墙钟时间、进程峰值 RSS、候选数、SWAP、深度、胜平负和失败信息。所有
任务单进程顺序运行；四分片吞吐数据不得与 V7 核心时间混用。

## 6. 统计与解释

主要表格报告每个时间倍率下的总 SWAP、逐线路胜平负和每条线路的重复方差。
如计算 bootstrap，抽样单位为公共线路，并把同一线路的三次重复作为一个簇。

最小接受条件不是“SMPR 必须赢”，而是：

- 10 个源文件哈希全部匹配；
- 10 个准备实例全部大于 10 逻辑比特并使用 heavy-hex；
- 映射、拓扑与路由轨迹审计全部通过；
- SMPR 相对其内部 20-seed LightSABRE 候选逐实例无 SWAP 退化；
- 任何失败和负结果都进入最终报告。

只有完成上述流程后，V7 数值才能加入论文结果部分。
